# 継続実行の仕組み

## 比較
| 方式 | 費用 | PC | AI (台本) | 音声 | 状態の保存 | 判定 |
|---|---|---|---|---|---|---|
| **オーナーの PC + cron / タスクスケジューラ** | 0 円 (電気代のみ) | 起動が必要 | claude CLI (サブスク内) | VOICEVOX 可 | PC 内 | **第一候補** |
| Claude Code のスケジュール実行 (クラウド) | 0 円 (サブスクの利用枠内) | 不要 | 可 | Open JTalk のみ | リポジトリに保存 (要・非公開化) | 第二候補 |
| GitHub Actions | 無料枠あり | 不要 | 有料 API が必要 | Open JTalk | Actions | 不採用 (有料 API) |

## AI が必要な処理 / 不要な処理
| 処理 | AI | Claude Code のセッションを閉じた後も動くか |
|---|---|---|
| 企画生成・台本・事実確認・週次会議の議事録 | 必要 (claude CLI) | PC の cron なら動く (CLI がログイン済みであれば) |
| 音声・映像・字幕・編集・サムネ・技術審査 | 不要 | 動く |
| アップロード・予約・分析・日報・ダッシュボード | 不要 | 動く |
`--no-llm` を付けると AI なしで動く範囲だけを実行する (AI の利用枠を使い切った日の代替)。

## 停止・異常時の動作
- **PC が停止・スリープ**: その時刻の実行は行われない。Windows は「StartWhenAvailable」で復帰後に実行。cron は次の時刻に実行。制作の途中で止まった動画は次回に続きから (状態は DB に保存)
- **ネットワーク未接続**: 制作 (AI 画像・台本) と投稿が失敗し、エラーを記録して次回に再試行。公開済みの予約は YouTube 側で実行されるため影響なし
- **重複起動**: ロックファイルで 2 つ目の実行は即終了
- **緊急停止**: `python -m ytops stop "理由"` またはダッシュボードの「停止」。停止中は制作・投稿をせず、分析と日報だけ行う

## クラウドで動かす場合 (第二候補) の手順
1. リポジトリを非公開にする (OWNER_TASKS 手順 0)
2. クラウド環境の設定 (セッションのタイトル横の環境メニュー → 編集) で環境変数 `YT_CLIENT_ID` `YT_CLIENT_SECRET` `YT_REFRESH_TOKEN` `YTOPS_REPO_PRIVATE=1` をオーナー自身が入力する (チャットには貼らない)
3. Claude に「毎朝 6 時に運営を実行するスケジュールを作って」と依頼 → 実行内容: `ytops load-state` → `ytops daily` → `ytops save-state` → git commit & push
